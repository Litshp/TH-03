# 数据整理题｜从这里开始

## 一句话任务

请写一个小程序，把一张混有**重复、修改和错误**的培训反馈表整理干净，再生成两张结果表。

不需要了解任何公司系统，也不需要生产经验。材料里出现的 WorkshopPulse 是虚构名字，无需查找；这三份文件就是全部背景。

**开始前**：如果打算使用 AI，先确认工具能导出完整对话，并从第一句话起为本题新建独立 session（要求见「允许使用 AI」）。

## 先认识三份输入

| 文件 | 它是什么 | 你用它做什么 |
|-|-|-|
| `sessions.csv` | 4 场培训活动的名单 | 确认反馈里写的活动是否真的存在；最后每场活动都要有一行汇总 |
| `feedback.csv` | 大家上传的原始反馈记录 | 从中找出能用的最终反馈，以及重复、修改和错误数据 |
| `rules.md` | 数据整理说明 | 按这里的规则判断什么能用、如何去重、要输出哪些列 |

CSV 是普通表格文本，可以用 Excel 或文本编辑器打开。第一行是列名，之后每行是一条数据。文件里混有正常反馈、重复上传、后来修改过的反馈和错误数据，需要你按 `rules.md` 逐行判断。

## 按这个顺序完成

1. 先看 `sessions.csv` 和 `feedback.csv`，弄清每一列表示什么。
2. 读 `rules.md`，列出检查、去重、选择最新反馈和汇总的顺序。
3. 写程序并运行。坏数据不能让整次处理失败，要进入拒绝清单。
4. 用同一份输入再运行一次，确认结果完全一样。
5. 用少量测试证明最容易出错的规则真的生效。

## 需要生成的两份结果

- `session_summary.csv`：每场活动一行，回答“最终有几个人反馈、平均几分、多少反馈提到了问题”。具体列名、排序、小数位和隐私规则见 `rules.md`。
- `rejected_rows.csv`：每条不能安全使用的原始数据一行，写出原始 `row_id` 和稳定、看得懂的拒绝原因。

## 运行环境

- 语言不限，但程序必须能在一台干净的 macOS、Linux 或 Windows 上，用该语言的标准工具链运行。推荐 Python 3.11 及以上（旧版本对部分 ISO 8601 时间写法支持不全），优先只用标准库；确需第三方依赖时，把安装命令写进说明。
- 运行命令的形式：`<你的命令> <输入目录> <输出目录>`，输入目录就是本材料目录，两份结果写到输出目录。
- 输出文件用 UTF-8 编码、`\n` 换行。

## 时间、投入与提问

- 收到题目后 3 天内提交（自然日）。建议投入约 2 小时，不设硬上限。若 2 小时内做不完，优先保证：程序能运行、两份结果已生成、说明里写清假设与未完成项。
- 这 2 小时里，**写出程序通常只占一小部分**；剩下的时间是留给你核对结果、跑边界情况、确认说明和代码说的是同一件事的。请在说明里把耗时**分开写**：读题与理解材料、产出代码、核对与验证、写说明各花了多久。我们不按总时长评分，但会看这个分布。
- 未完成不等于不合格，但必须说明已完成什么、哪里停止以及下一步会怎么做。
- 做题期间不接受提问。材料没有定义的规则，不要悄悄猜一个答案：把你的假设写进说明，并选择一种每次运行都得到同样结果的处理办法，或者把无法放心判断的数据单独列出来。

## 允许使用 AI

可以使用任何 AI 工具，用哪一家、用多少、让它做多少都不加减分——**全部交给 AI 完成也可以**。我们要看的只有一件事：你能不能为这份结果负责。

请在说明里回答三个问题（没有使用 AI 的，按同样三问回答你自己的做法）：

1. **为什么可信**：这份结果凭什么信得过？你做了哪些验证，证据在哪；其中哪些做成了可重复执行的东西（脚本、测试、一条命令），哪些只是一次性看了一眼。
2. **哪里没把握**：哪些没有验证、哪里可能出错、什么情况下你的结论会不成立。
3. **关键取舍为什么这么选**：材料里没有给标准答案的地方，你最后选了什么、为什么。方案是 AI 提的也没关系，说清楚你为什么接受它。

再用一小段写清楚**你这次的 AI 工作方式**：用了什么工具和模型；给了 AI 哪些上下文（规则文件、技能、记忆、预置提示词等，写清各自干什么就行）；验证是怎么闭环的；你觉得它这次最可能在哪出错。规则文件和技能**不强制附原件**，涉及公司内部信息的只写用途、不要贴内容。

**开始前先确认你的工具能导出完整对话**，并从第一句话起为本题新建独立 session。可接受的原始记录形式：

- Claude Code、Codex 等命令行工具：会话原始文件（通常是 `.jsonl`），整份提交。
- ChatGPT、豆包、Kimi 等网页或客户端：官方“分享链接”或“导出数据”功能的产物。
- Cursor、Copilot 等无导出功能的工具：全程不裁剪的录屏，或按时间连续的整页截图。

不要向 AI 输入真实公司数据、账号、密钥或个人隐私。工具自动带出的本机路径、用户名等属可接受范围，不需要删改。若日志包含密钥、账号、个人隐私或与本题无关的公司数据，可以自行脱敏：只把敏感片段原位替换为 `[REDACTED:类型]` 占位（如 `[REDACTED:密钥]`），不要删除整行或整条消息，也不要改动其他内容。脱敏后须在说明中写明脱敏了哪些类型、涉及哪些日志文件、用什么方式处理（手工或脚本，脚本请一并提交）。本机路径、用户名如确需脱敏，同样原位替换并声明。用了多个 session 时，可在说明里用几句话标注各自用途，日志本身不动。**等最后一次 AI 回复写完之后再导出**，否则导出的只是中途快照。日志只用于核实过程真实性，不按行文风格评分。Claude Code 的会话文件在 `~/.claude/projects/<项目目录>/` 下。

## 最后提交

把以下内容打包为一个 zip，回复到发题邮件；或提供一个招聘方可访问的仓库链接。

1. 可运行的代码。
2. 一条从原始输入生成结果的命令。
3. 实际生成的 `session_summary.csv` 和 `rejected_rows.csv`。
4. 说明：主体一页以内，至少包含关键处理步骤、哪里没有完成以及为什么、实际耗时，以及「允许使用 AI」一节里的三个问题和 AI 工作方式那一小段（含所用工具与导出方法）；假设清单可另附，不限篇幅。
5. 你认为最有价值的少量测试。测试数量不作为评分依据。
6. 使用 AI 时，提交 `AI_SESSION_LOGS/`，其中包含本题用到的全部原始 AI session log：一个 session 一份原始导出，多个 session 全部提交，不合并、不节选；除按「允许使用 AI」一节的规则脱敏外不改写。未使用 AI 时不创建该目录，并在说明中明确写明。

提交后会进行 15 分钟现场答辩，面试官只围绕你的提交物追问，现场禁用 AI。我们不要求唯一实现，也不会按是否使用某个库评分。
